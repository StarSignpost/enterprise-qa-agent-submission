## 1. 依据与要求层级

主要依据为用户提供的本地笔试原题中的“试卷说明”“GitHub 交付规范”和第 3 题“企业知识问答 Agent”。仅概括业务与交付要求，不复制卷面个人信息、专属访问链接或令牌。

| 标记 | 含义 | 适用原则 |
| --- | --- | --- |
| H | 原题硬性要求 | 必须覆盖；不得用本项目设计替代或降低。 |
| U | 用户协作约束 | 本项目必须遵守，但不冒充原题规定。 |
| D | 本项目设计选择 | 为缩小范围、便于验证而选定，可在后续阶段说明理由后调整。 |

原题建议投入约 3 小时，要求记录实际用时与未完成部分；3 小时不是必须编造达到的工时，也不是通过标准。原题允许 CLI、HTTP API、Notebook 三选一；本项目选择 CLI、Python 3.10+ 标准库与 unittest，真实服务按用户选择改为 DeepSeek Responses，不引入 Agent 框架。

## 2. 用户、目标与范围

- 用户：需要查询企业制度或产品信息的员工。
- 目标：依据可追溯资料提供可靠答案；证据不足、冲突或工具失败时如实说明。
- 输入：用户问题、可选对话历史，以及带文档 ID、版本日期的合成 FAQ 或制度。
- 必备业务工具：文档检索、片段读取。工具可以是本地函数或 Mock；模型决策的真实性单独验证。
- 输出：回答、引用文档 ID 与原文片段、资料缺口、任务状态。
- 核心范围：CLI、合成资料、两个业务工具、真实模型循环、离线 Mock、执行上限、Trace、测试与交付文档。
- 工具阶段只实现资料与工具；当前阶段已实现并执行模型循环与真实验证；直接工具调用或 Mock 仍不能替代真实模型业务验收。核心项目不扩展界面、部署、多 Agent 或复杂基础设施。

## 3. 本项目设计选择与取舍

以下是 D 类选择，不能表述为原题要求：

| 编号 | 设计选择 | 理由与边界 |
| --- | --- | --- |
| D01 | 使用本地合成资料；用 JSON 规划输入、输出与资料快照，用 JSONL 规划 Trace。 | 控制依赖并便于核对。字段及具体实现留待架构阶段确定；不引入真实企业隐私资料。 |
| D02 | 检索提供候选摘要；引用前读取原文片段。 | 将候选发现与证据核对分开，便于验证引用。工具不直接给出预设最终回答或模型动作。 |
| D03 | 使用可配置的决策步数上限；无效动作与失败的模型调用尝试也消耗额度。 | 防止只限制工具调用却仍能无限循环。默认数值及计数细节在方案阶段确定；触顶且未结束时必须明确未完成。 |
| D04 | 规划四种状态：`completed`、`needs_clarification`、`incomplete`、`failed`。 | 分别表示证据充分且任务完成、需要用户澄清、资料不足或执行触顶未完成、故障导致失败。状态名称是本项目选择，原题只要求如实表达状态。 |
| D05 | 用真实模型运行六项业务验收；用离线测试补充计数、异常及记录格式检查。 | 这是本项目的验证安排。离线结果不能替代真实模型效果证据。 |
| D06 | 以事实、引用、状态和可观察动作判断结果，不绑定整段自然语言或唯一调用顺序。 | 允许模型选择合理路径；示意路径不能变成预设执行脚本。 |

本项目状态约定：未解决的文档冲突使用 `needs_clarification`；资料外且无法取得证据使用 `incomplete`；持续工具故障导致无法完成使用 `failed`，若先耗尽执行额度则使用 `incomplete` 并记录触顶原因。故障后若模型取得了足够的有效证据，可以正常完成，但必须保留实际故障与恢复记录。

### 6.3 两条路径的核对方式

路径示意仅用于说明验收意图，不要求硬编码：

- 路径 A：取得一致证据后，模型决定回答并结束。
- 路径 B：观察到资料冲突后，模型决定补查或读取更多证据；仍无优先级依据，模型请求确认。

执行后必须指出各路径的关键工具观察、观察之后实际发生的模型动作，以及简要依据。若实际记录没有体现至少两条结果驱动的不同路径，则 G02 仍未满足，不能用预设日志补齐。

### 6.4 验收结果记录规则

最终在 `docs/03-evaluation.md` 逐项记录要求编号、预期、实际、结论、证据路径与适用实现版本。结论使用“未运行”“通过”“失败”“受阻”；“通过”必须同时有实际执行记录和符合失败判据的核对结果。规划时未生成任何通过结果；当前各项实际状态见第 11 节。

测试报告置于 `examples/checks/`，明确标注真实模型、离线 Mock 或静态检查。离线保护测试通过、静态检查无误和真实模型业务验收通过是不同结论，不能互相替代。没有模型权限、密钥、额度或网络时，记录具体阻碍及未验证项，保留 Mock 流程入口，但不能宣称已满足真实决策要求。
